The Problem

Large Models, Real Constraints

Modern AI models can contain billions of parameters and require substantial storage, memory, and compute resources.

Storage

How much space the model representation occupies on disk. A 27B parameter model in FP16 requires approximately 54 GB of storage.

Runtime Memory

How much memory is required during inference. This includes the model weights, KV-cache, activations, and overhead.

Compute

How much computation is required to perform inference. This depends on the model architecture, precision, and hardware capabilities.

Compiler Pipeline

Seven Stages of Transformation

Click on any stage to learn more about what happens during compilation.

01
LOAD
Load model metadata and tensors from supported formats (PyTorch, safetensors, NumPy).
02
ANALYZE
Examine parameters, tensors, dtypes, architecture, storage, and runtime requirements.
03
PLAN
Choose compression strategy based on model characteristics, hardware, and constraints.

TRANSFORM
Apply the selected representation transformation (INT8, INT4, Binary, Ternary, etc.).

VALIDATE
Check numerical reconstruction, artifact integrity, size, and metadata consistency.

EXPORT
Create a versioned LDMARK artifact with all necessary metadata and validation info.
07
RUNTIME
Load and execute the compiled representation on the target hardware.

Compression Lab

Research Areas

Current and future research directions for model compression.

Uniform Quantization Active

INT8 and INT4 quantization with group-wise support. Maps floating-point values to integer representations with configurable bit widths.

Ultra-Low-Bit Experimental

Binary (1-bit) and Ternary (~1.58-bit) representations. Extreme compression with significant accuracy trade-offs.

Non-Uniform Experimental

Codebook quantization, group-wise codebooks, and learned binary representations. More complex but potentially more accurate.

Future Research Future

Mixed precision, direct low-bit computation, compression-aware training, and optimized CPU/GPU kernels.

Artifact Format

LDMARK Artifact Structure

A compiled LDMARK artifact is a self-contained package with all necessary metadata.

model.ldmark/ │ ├── manifest/ │ ├── config.json # Model configuration │ └── version.json # Artifact version info │ ├── metadata/ │ ├── model_info.json # Architecture, parameters │ └── compression.json # Compression settings │ ├── tensors/ │ ├── layer_00.bin # Compressed tensor data │ ├── layer_01.bin │ ├── layer_02.bin │ └── ... │ ├── compression_metadata/ │ ├── scales.bin # Quantization scales │ └── codebooks.bin # Codebook data (if used) │ └── validation_metadata/ ├── metrics.json # Reconstruction error └── checksums.json # Integrity verification

Key Point: The original model does not need to be present for an artifact-aware runtime to inspect the compiled representation.

Principles

Research Principles

Five guiding principles for honest compression research.

01

No Fake Compression

Only report measured or mathematically derived results.

02

Storage ≠ Runtime Memory

Never confuse a small model file with low inference memory.

03

Feasibility ≠ Quality

A representation fitting on a laptop does not prove that it preserves model capability.

04

Hardware Matters

The same representation can behave differently across hardware backends.

05

Measure Everything

Compression ratio, reconstruction error, runtime behavior, and memory usage should be independently evaluated.
